# NetShield AI

NetShield AI is a local network anomaly detection and predictive intrusion monitoring platform. Milestones 1 and 2 provide a FastAPI backend, SQLite persistence, JWT/RBAC authentication, CICIDS2017 chunked analytics, leakage-safe preprocessing, Isolation Forest anomaly detection, Random Forest attack classification, risk scoring, and a browser dashboard.

## Architecture

`CICIDS2017_improved/*.csv` -> chunked loader -> preprocessing pipeline -> Isolation Forest + Random Forest -> FastAPI -> `frontend/` dashboard.

The repository currently contains CICIDS2017 files only. The loader recognizes common UNSW-NB15 locations and label names, but no UNSW files are present locally, so UNSW training is not reported as complete. Dataset analytics are explicitly corpus-based; live packet capture is not falsely represented as implemented.

## Repository structure

- `backend/app/`: configuration, SQLAlchemy models, API routes, security, data and ML services.
- `backend/scripts/train_models.py`: trains and evaluates persisted models.
- `frontend/`: dependency-free browser dashboard consuming live API responses.
- `tests/`: backend, security, data-loader, and risk-score checks.
- `docs/technical-pipeline.md`: preprocessing and detection design.
- `CICIDS2017_improved/`: local raw flow CSVs; they are not modified by the application.

## Local setup

Python 3.9+ is supported. Install dependencies and optionally configure environment variables:

```powershell
python -m pip install -r requirements.txt
$env:NETSHIELD_JWT_SECRET = "a-local-secret-at-least-32-characters"
```

Supported variables are `NETSHIELD_DATABASE_URL`, `NETSHIELD_JWT_SECRET`, `NETSHIELD_JWT_EXPIRY_MINUTES`, `NETSHIELD_CORS_ORIGINS`, `NETSHIELD_DATA_ROOT`, and `NETSHIELD_MODEL_ROOT`. SQLite is the default local database; PostgreSQL can be selected with a SQLAlchemy URL.

## Run the project

Train on a reproducible sample drawn across all local dataset files:

```powershell
python -m backend.scripts.train_models
```

Start the API:

```powershell
python -m backend
```

Open `frontend/index.html` in a browser. The dashboard registers or signs in an analyst, then loads `/api/traffic/analytics`. For a browser security policy that blocks local file requests, serve the folder with `python -m http.server 8080 -d frontend` and open `http://127.0.0.1:8080`.

## API

- `GET /health`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/traffic/analytics` (authenticated)
- `POST /api/ml/predict` (authenticated)
- `GET /api/ml/metrics` and `GET /api/ml/model-info` (authenticated)
- `GET /api/admin/users` (administrator only)

Prediction input is a JSON object containing the feature names used during training. The response contains the model prediction, attack probability, confidence, anomaly flag, risk score, and severity. Passwords use PBKDF2-HMAC-SHA256 and are never stored in plaintext. The first registered account is an analyst; administrator promotion is intentionally a database/configuration operation rather than an open registration privilege.

## Data and ML pipeline

CSV files are read in chunks. Rows with missing labels, invalid numeric values, or duplicates are removed. Identifiers, IPs, flow IDs, and timestamps are excluded from modeling. Numeric and categorical transformations are fit only on the training partition. The supervised model is a class-balanced Random Forest; the unsupervised baseline is Isolation Forest. Evaluation persists accuracy, macro and weighted F1, precision, recall, classification report, and confusion matrix to `models/metadata.json`.

No metric or prediction is hardcoded. The dashboard displays only values returned by the local API. Generated database, model, and processed-data artifacts are ignored by Git.

## Milestone status

Milestone 1 is implemented for local CICIDS2017 analysis: architecture, backend/frontend integration, database structure, authentication/RBAC, ingestion/preprocessing, monitoring analytics, and dashboard are present. A live packet collector and UNSW-NB15 execution remain explicit extensions because neither exists in the supplied repository/data.

Milestone 2 is implemented for local CICIDS2017: anomaly detection, attack classification, evaluation reports, inference API, transparent risk scoring, persisted model metadata, and dashboard model status are present. Actual evaluation metrics are generated by `python -m backend.scripts.train_models` on the current local files and are intentionally not claimed here before that command is run.

## Contributing Guidelines (For Interns / Collaborators)

All interns added as collaborators to this repository must follow the branch workflow below. **Direct commits or pushes to the `main` branch are not allowed.**

> Note: `main` only contains the `LICENSE` and `README.md` — it is not used for active development. There is no need to pull the latest `main` into your branch at any point.

### 1. Branch Naming

- Every intern must create their own branch off `main`, named after themselves.
- Suggested naming convention: `firstname-lastname` (all lowercase, hyphen-separated).
  - Example: `john-doe`, `aisha-khan`

### 2. How to Create Your Branch

**Option A — Clone and push (recommended)**

```bash
# Clone the repository
git clone https://github.com/springboardmentor442n-coder/Network-Anomaly-Detection-and-Predictive-Intrusion-Monitoring-Platform.git

# Move into the project folder
cd Network-Anomaly-Detection-and-Predictive-Intrusion-Monitoring-Platform

# Create and switch to your own branch (off main)
git checkout -b your-name

# ... make your changes ...

# Stage, commit, and push your changes to YOUR branch only
git add .
git commit -m "Describe your change here"
git push origin your-name
```

**Option B — GitHub UI upload**

1. Go to the repository on GitHub.
2. Switch the branch dropdown from `main` to your own branch (create it first via **Branch: main → View all branches → New branch**, named after yourself).
3. Once on your branch, use **Add file → Upload files** to upload your code.
4. Commit directly to your branch (not `main`).

### 3. Rules

- ❌ Do **not** push or upload code directly to `main`.
- ❌ Do **not** push code to another intern's branch.
- ✅ Only push/upload code to the branch that carries your own name.
- Keep uploading/pushing your code to your branch regularly as you make progress. No pull requests are required — your branch itself is the deliverable.

### 4. Summary

| Action | Allowed? |
|---|---|
| Push to `main` directly | ❌ No |
| Create your own branch from `main` | ✅ Yes |
| Push/upload code to your own branch | ✅ Yes |
